# emoji-reaction

2026-09-24, transformation engine (hand-rolled component, no shadcn golden pair). Migrated: the `Slot`/`asChild` trigger now uses Base UI `useRender` with a `render` prop; `@radix-ui/react-slot` removed from package.json.

## Changed

- `components/ui/emoji-reaction.tsx`
  - `import { Slot } from "@radix-ui/react-slot"` -> `import { useRender } from "@base-ui/react/use-render"`.
  - Prop `asChild?: boolean` -> `render?: useRender.RenderProp<{ open: boolean }>`. The trigger is built with `useRender({ defaultTagName: "button", render, ref: setTriggerRef, state: { open }, props })`; the previous `<Trigger>` JSX block is replaced by `{trigger}`.
  - Behavior props (aria-*, `onPointerDown`, `onClick`, `type`) are passed through `props`, so `useRender` merges them with the props of the `render` element (event handlers chained, `className` joined, refs merged).
  - Default styling and icon content apply only when `render` is not passed, same as the old `asChild` branch. When `render` is passed, the component's `children` become the trigger content (the render element's own children win if it has any).
- `package.json` / `pnpm-lock.yaml`: `pnpm remove @radix-ui/react-slot`.

Leftover scan: `grep -n "radix-ui\|@radix-ui\|Slot\|asChild" components/ui/emoji-reaction.tsx` finds nothing. No project source file imports radix anymore.

## Left alone

- `@radix-ui/react-slot` is still in `pnpm-lock.yaml` as a transitive dependency of `cmdk` (via `@radix-ui/react-dialog` / `react-primitive`). cmdk is not radix-owned code and is intentionally untouched.
- `components/ui/button.tsx` and `components/docs-copy-page.tsx` use an `asChild` prop, but it is not radix-backed. Out of scope.
- `registry/new-york/emoji-reaction.tsx` was already on Base UI (Popover). No change.
- Pre-existing lint findings in `components/ui/emoji-reaction.tsx` (sort-keys, curly, nested ternaries): 57 before, 56 after. Not introduced by this migration.

## Behavior changes

- Public API: `asChild` no longer exists. Consumers write `<EmojiReaction render={<MyButton />}>…</EmojiReaction>` (or `render={(props, { open }) => …}`). No consumer in this repo used `asChild`.
- The trigger now receives a `data-open` attribute while the bar is open (generated by `useRender` from `state`). This is additive and has no default styling.

## Verify by hand

- Click the trigger: the bar opens, the first emoji gets focus, and ←/→/Home/End move focus.
- Press on the trigger, drag onto an emoji, release: that emoji is picked and bursts.
- Escape closes the bar and focus returns to the trigger. Clicking outside closes it.
- Pass `render={<button className="…">React</button>}`: the custom element opens/closes the bar, keeps its own classes, and gets `aria-expanded` and `data-open`.
